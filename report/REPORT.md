## 1. Зачем DAgger

Пайплайн EML состоит из DATA-фазы (символьная регрессия формулы к ответам
оракула на его же траекториях) и GAME-фазы (эволюция по реальному счёту в
игре). Комментарии в коде фиксируют, что формула после DATA-фазы почти не
набирает очков, хотя хорошо приближает оракула, и что GAME-фаза существует
именно поэтому.

Это классический сдвиг распределения из имитационного обучения. DATA-фаза
обучается на состояниях, которые посещает **оракул**. Сама формула ошибается,
попадает в состояния, которых оракул никогда не видел, и данных для них у неё
нет. Ошибка накапливается с длиной эпизода: для behavioural cloning (BC) это
O(T²ε), для DAgger O(Tε) (Ross, Gordon, Bagnell, 2011).

DAgger лечит то же самое со стороны данных, а не фитнеса. На каждой итерации:

1. играет смесь `β·оракул + (1−β)·текущая формула` (монетка на каждом шаге);
2. оракул размечает **каждое** посещённое состояние (в Tetris это все
   допустимые размещения фигуры);
3. данные добавляются к общему датасету, формула переобучается с тёплого старта;
4. формула оценивается на VAL, лучшая итерация выбирается по VAL.

Итерация 0 при β = 1 и есть BC, поэтому BC получается как первая строка истории
DAgger без дополнительных затрат.

## 2. Реализация

| Файл | Что делает |
|---|---|
| `emlcore/dagger.py` | Общий цикл `run_dagger(collect_fn, fit_fn, eval_fn, …)` и расписания β (`exp`, `linear`, `zero`). Ничего не знает про EML и игры, поэтому подходит и для классических студентов (VIPER в соседней ветке). |
| `tetris/dagger_distill.py` | Адаптер Tetris: сбор смешанных траекторий, разметка CNN-оракулом всех размещений, DATA-фаза на объединённом датасете, четыре варианта студента, отчёт на TEST. |
| `tetris/eml_distiller.py` | `evolve_formula(..., init_trees=[...])`: тёплый старт, половина начальной популяции это мутанты прошлой формулы. Имя и смысл аргумента совпадают с веткой `ga-resume-checkpoints`, при слиянии остаётся её версия. |
| `flappy_bird_with_ai/dagger_distill.py` | Адаптер Flappy Bird: то же для MLP-оракула, фитнес по сбалансированной точности действия. |
| `report/make_report.py` | Пересборка таблиц этого отчёта. |

Протокол оценки тот же, что во всём проекте. Пулы сидов окружения TRAIN, VAL и
TEST не пересекаются. DAgger-траектории берут сиды из отдельного потока (от
9 000 000). TEST трогается один раз на каждого финального студента, причём
оракул играет на тех же сидах (парное сравнение).

## 3. Tetris

**Оракул:** TetrisCNN + PPO, обучен заново в этой ветке (`main.py train`,
конфиг по умолчанию, сид 0). Остановился по цели 100 линий после 876 тыс.
размещений (28 мин на CPU). На TEST (30 игр, лимит 300 размещений, как
`EML_INGAME_MAX_PLACEMENTS`) он даёт **111.8 ± 4.1** линий. Тот же чекпоинт
использует сравнение с классическими методами.

**Бюджет на один сид ГА:** D₀ состоит из 40 эпизодов оракула (≈ 250 тыс.
строк, 10.9 тыс. шагов). Каждая DATA-фаза идёт с конфигом по умолчанию (600
поколений × 600 особей, NSGA-II, patience 120). У DAgger 5 итераций по 10
эпизодов смеси, β = 0.5ⁱ. GAME-фаза берёт 15 поколений × 30 особей, это
сокращённая версия, одинаковая для BC+GAME и DAgger+GAME.

## 4. Flappy Bird

**Оракул:** `models/best_ga.pt` (GA + MLP 4→16→1, из репозитория). Он не
проигрывает ни одной игры, поэтому при лимите 3000 кадров набирает ровно 32
трубы на каждом сиде TEST. Это потолок шкалы.

**Функция потерь.** Регрессия к сигмоиде оракула, как в DATA-фазе
`eml_distiller`, здесь не работает. Выход оракула лежит в [0.44, 0.56], а
взмах приходится примерно на 4 % кадров, поэтому выигрывает почти константа.
Регрессия к логиту не лучше: даже метод наименьших квадратов (R² = 0.81)
даёт всего 0.65 сбалансированной точности действия, хотя линейный
классификатор на тех же данных доходит до 0.94. Поэтому студент BC/DAgger
учится на **сбалансированную точность действия** (взмах / нет). Строки
каждой итерации DAgger получают одинаковый суммарный вес, иначе 90 тыс.
кадров оракула заглушают пару тысяч кадров, которые проживает студент.

**Бюджет на сид ГА:** D₀ состоит из 30 эпизодов оракула (90 тыс. кадров).
Фит идёт 300 поколений × 400 особей, у DAgger 6 итераций по 60 эпизодов.
Эталон EML-GAME (текущий `evolve_eml`) получает 150 поколений × 200 особей.

## 7. Воспроизведение

```bash
cd tetris
python main.py train                                   # оракул, ~30 мин CPU
python dagger_distill.py --seeds 0 1 2 3 4 5 --iters 5 # основная таблица
python dagger_distill.py --seeds 0 1 2 --iters 5 --chunk-balance --tag cb
cd ../flappy_bird_with_ai
python dagger_distill.py --seeds 3 --iters 6 --generations 300 --population 400
cd .. && python report/make_report.py
```

Сырые данные: `tetris/results/dagger/**/dagger_{summary,iterations,episodes}.csv`
(по строке на игру TEST, у оракула на тех же сидах), формулы в
`formula_*.json`; для Flappy `flappy_bird_with_ai/results/dagger_*.csv`.
